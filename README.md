# Research Companion Scientific Agent

面向研究与资料整理场景的智能助手，使用 Go 构建后端，Vue 3 构建交互界面。

项目围绕流式对话、文档检索、会话记忆、工具调用与多步骤任务执行逐步完善。技术路线采用 PostgreSQL 持久化、Milvus 向量检索、Elasticsearch 全文检索和 Neo4j 知识图谱。

## 会话记忆与偏好

短期记忆按 `MaxTurns * 2` 条消息维护最近窗口，提供追加、历史恢复、计数和快照；非正窗口保持为空。恢复历史保留输入时间，输入和快照均复制存储。模块自身使用进程内存；应用层已按用户分桶并通过注入的回调懒加载历史。公开方法持锁，直接访问导出字段需要调用方同步。

偏好模块支持单条与批量键值保存、快照和上下文格式化，忽略空键或空值。简单中文规则按“我喜欢／我爱／我叫”完整短语提取值；复杂语义和模型提取由上层处理。PostgreSQL 仓储按用户 ID 参数化保存与读取，行解析或结果流读取失败时记录日志并返回空结果，避免使用不完整的偏好。

长期记忆仓储保存用户 ID、原文、重要性、向量、分类、标签、槽位、隔离和替代关系，支持按用户读取、更新、批量重要性刷新、删除和隔离标记。`Load()` 会加载所有用户及 legacy 数据；调用方需按场景选择用户范围读取。更新与删除按条目 ID 执行，上层负责用户授权。

读取行或向量解析失败会丢弃整次结果。替代关系的旧记录标记与新记录链接在一个 PostgreSQL 事务中执行；新 ID 为正数时必须确认更新到一条新记录，链接失败或目标缺失会回滚。`newID == 0` 保留只标记旧记录的兼容路径。

已通过 14 项合成与 SQL Mock 检查，覆盖窗口边界、历史与快照复制、公开方法的并发调用、偏好规则、用户查询参数、元数据恢复、批量 SQL、读取错误及替代事务提交和回滚。没有验证真实 PostgreSQL 或运行 Go race 检测。仓储沿用无 error 返回值的接口，错误主要通过日志和空结果／失败 ID 表示；内存更新与仓储写入尚无统一事务。长期记忆领域层提供向量余弦召回和词袋降级，按用户、分类、标签与年龄筛选，默认排除隔离、已替代和已删除条目。隔离条目不会阻止同内容的新记忆写入。空用户写入归入 `legacy`，普通召回必须提供用户；全用户审计开关、按 ID 的操作及零新 ID 的替代兼容路径需要上层授权。输入、读结果和配置的可变字段均复制；直接访问导出字段仍需同步。

合并与去重只处理同用户、同分类的活跃条目，保留较重要条目的 ID、分类和来源标签，输出最终保留条目的更新；单条记忆也会衰减和按 TTL 淘汰。删除保护钩子可保留指定记录，隔离与已替代条目保留供审计。衰减以 `UpdatedAt` 为起点，旧数据回退到 `CreatedAt`，重要性差值达到 0.01 才生成衰减更新。该时间戳也用于其他写入，旧仓储没有保存衰减锚点，尚无跨重启的精确衰减保证。

`PlanConsolidation` 不修改缓存，生成携带预期版本的更新与删除计划；`Consolidate` 是直接修改内存并返回待写回结果的兼容入口，两者都没有自行执行 PostgreSQL 事务。新替代 ID 为正数时必须存在、归属一致且不能替代自身。

一致性契约包含版本化记录、Outbox 事件和已提交变更集。内容哈希复制并排序标签与替代 ID，规范删除时间的时区，拒绝非有限数值。`ApplyCommitted` 在修改前校验整批变更，拒绝重复 ID、现有记录的归属变化、过旧版本及同版本不同哈希；`ReplaceCommitted` 用权威记录重建缓存并排除墓碑。版本检查只覆盖仍在缓存中的记录，删除后的旧消息重放需要上层防护或权威重载。事务仓储与投影批次入口已提供；应用层联通与调度仍待后续整合。

本阶段 38 项测试、22 个子用例覆盖哈希边界、合并与衰减、版本校验、替代关系、用户隔离、隔离恢复、快照复制和公开方法并发调用。检查使用合成数据，未运行 Go race 检测或真实 PostgreSQL、图谱、向量与模型联通；完整应用尚不能启动。

## 应用层记忆链路

短期历史和偏好按用户分别懒加载，匿名请求不创建桶；同一用户的并发首次访问只预热一次。历史恢复受短期窗口限制。预热失败以空桶继续，没有自动重试或桶淘汰；回调持有各自桶表的写锁，不同用户的首次预热也会等待。长期记忆启动时优先读取版本化权威记录，失败时不切换到旧仓储；没有注入事务仓储时才保留旧数据恢复路径。图记忆在长期记忆恢复后关联，实际召回仍按用户过滤。

新记忆先提交 PostgreSQL 记录和 Outbox，再校验回执归属、ID 与版本并更新缓存。提交、合并和冲突替代在同一记忆栈实例内协调；合并前从权威行保留缓存尚未存储的向量模型与修订信息。缓存应用失败时全量回读源记录，回读仍失败则清空缓存以停止召回不确定数据。数据库成功提交仍返回已提交记录，缓存故障另行记日志，之后需要重新加载权威状态；数据库和内存并非原子事务，也不保证多进程缓存自动同步。

记忆抽取分用户陈述和问答派生两路，执行整段、键值和最终文本检查，拒绝空白条目和未知来源。规则未命中时可由模型分类，分类和槽位限制在已知值内。来源标签保留抽取路径；问答派生不写用户偏好。用户偏好在记忆提交成功后才更新，偏好仓储仍是独立写入，无错误返回接口，没有与记忆事务一起回滚的保证。问答主题由提示词约束，不构成事实正确性验证。

冲突判断只使用同用户、同分类的活跃候选，模型返回的 ID 必须属于候选且不能重复；缺失或外部用户的新条目不触发替代。判定后复查新旧源记录、归属和版本，通过单个事务保存旧条目的替代状态、新条目的引用与投影事件，再应用已提交结果。版本变化或事务失败不先改缓存；这一入口不使用旧仓储的零新 ID 替代兼容路径。

敏感内容检测覆盖若干密码、Token、PAT、私钥头、个人信息和指令模式，并过滤临时性内容。PII 命中片段固定脱敏，抽取日志不记录原文值；规则是启发式检查，仍有误报和漏报，不能替代授权与数据治理。

检查使用完整记忆源文件、实际依赖、事务接口替身及本机模型 HTTP 服务；仅从真实 Agent 类型中选择这些路径使用的字段来运行，未提供缺失运行模块的模拟实现。完整聊天包、真实 PostgreSQL／图谱／向量／模型服务和 Go race 检测仍未验证。

## 记忆事务与 Outbox

事务仓储在同一个 PostgreSQL 事务中保存记忆、版本、内容哈希和对应的 Milvus／Neo4j Outbox 事件，只有数据库提交成功才返回变更集。创建支持可选关系事件；更新和软删除同时匹配条目 ID、用户 ID、预期版本及未删除状态。普通更新保留数据库中已有的隔离与替代元数据；哈希和事件载荷取自数据库返回的完整记录。

合并计划按 ID 顺序锁定条目，校验整批归属和版本，拒绝重复 ID。合并后的分类、标签、槽位、向量模型、访问时间、隔离与替代关系均写入；任何行、哈希、事件或提交失败都不返回部分已提交成果。活跃加载和分页属于内部恢复／对账接口，会读取所有用户；活跃加载只排除墓碑，调用方仍需控制授权和召回过滤。

Outbox 按目标和 ID 顺序用 `FOR UPDATE SKIP LOCKED` 领取待处理或租约已过期的事件，在同一事务内标记处理状态。处理中的 `available_at` 保存数据库时钟计算的租约截止时间；过期重新领取会累计中断尝试次数。成功、重试和死信更新要求事件仍为 processing，校验影响一行；重试保存下次可用时间、错误和尝试次数。修复入队按 key 去重，缺省事件 ID 根据 key 生成稳定 UUID。相同 key 的已处理事件在条目、版本、事件类型、目标和用户都匹配时可重新入队；pending、processing 和 dead 事件保持原状态和尝试次数，不自动重启死信。

当前投递语义是至少一次；状态接口只携带事件 ID，没有领取令牌和租约续期，不能阻止旧 worker 更新已被重新领取的事件。投影批次设置从领取前开始的租约截止时间，取消或到期后停止确认，但 context 不能代替数据库领取令牌。当前部署需保证每个目标只有一个活动消费者；持续调度仍在后续计划，对账提供批次入口；事务仓储本身不会连接向量或图服务。

事务与 Outbox 的 25 项测试、46 个子用例覆盖 SQL 参数、完整元数据与事件载荷、版本和用户归属、回滚、读取错误、领取租约、状态更新、修复 UUID 与去重。检查使用 SQL Mock，未在真实 PostgreSQL 执行 SQL、验证并发锁或故障恢复，也未运行 Go race 检测；完整应用仍在整合中。

## 记忆投影与消费

公共投影器校验事件目标、类型、条目 ID、用户、版本及已有内容哈希，再读取当前状态。旧版本不覆盖新版本；相同版本和哈希的重复事件跳过，相同版本不同状态返回冲突。空哈希兼容旧记录及孤儿删除，不能提供完整内容校验。支持删除墓碑的存储会保留版本和哈希，防止较旧事件在删除后重新创建记录；只实现旧 Delete 接口的第三方存储仍不能保留该水位。

Milvus 使用独立集合 `long_term_memory_vectors`，保存 ID、用户、版本、哈希、删除标记和向量。初始化检查既有字段和维度，建立 Flat cosine 索引后加载；不兼容集合返回错误，需要显式迁移。写入拒绝维度不符、非有限或超出 float32 范围的向量；读取使用强一致性并校验完整列。删除保留带占位向量的墓碑，直接搜索该集合必须排除 `deleted` 条目。对账分页使用 SDK 的主键有序迭代参数，保留删除标记并检查严格递增的 ID；要求集合为强一致性，避免把本地排序的有限子集当成完整游标页。

Neo4j 读取返回版本、哈希与删除标记，行解析或延迟错误时丢弃结果。写入通过节点写锁再次检查版本和归属，在一个驱动托管事务内保存元数据并按 `Supersedes` 重建同用户 `SUPERSEDES` 审计关系；引用节点尚未投影或归属不符时整次回滚，等待重试。节点和关系 upsert 事件都同步这一完整视图，没有自动推断任意语义关系。删除保留版本墓碑，清理活动关系并保留 `SUPERSEDES` 审计链接；召回仍需过滤本地记忆的删除、隔离与替代状态。

Outbox worker 提供 `RunOnce` 批次入口，默认每批 100 条、30 秒租约、最多 10 次失败尝试；持续后台循环由后续应用入口接入。单个 worker 的批次串行执行，从领取前设置整批截止时间，取消或到期后停止调用和确认，未确认事件等待租约恢复。失败按最多 1,024 秒指数退避，达到上限进入死信；projector panic 作为失败处理，状态写入失败返回错误。调用方需设置非空 worker ID，外部调用必须响应 context。

投递仍是至少一次。公共投影器只协调单个实例，Milvus 没有跨进程比较并写入；现有 Outbox 确认接口也没有领取令牌和续期。当前需每个目标一个活动消费者，不能宣称多进程恰好一次处理。墓碑尚无自动清理策略；对账批次已提供，持续调度及关系级漂移检测仍待接入。

本阶段通过安装的 SDK、驱动和仓储 Mock 检查事件校验、乱序与重复、持久墓碑、向量和字段、索引顺序、Neo4j 事务与关系回滚、延迟错误，以及 worker 取消、到期、重试、死信和并发批次。尚未验证真实 PostgreSQL／Milvus／Neo4j 联通、真实 Cypher 与锁行为、多进程故障恢复或 Go race 检测；完整应用和前端仍在逐步整合。

## 投影对账与修复

对账以 PostgreSQL 为权威源，默认每页 500 条，完整读取源记录和目标的有序分页后比较缺失、旧版本和删除状态，拒绝重复 ID、无序页和读取错误。初始全量读取阶段失败时不根据部分结果排入修复。当前会保留整轮源记录和目标元数据，空间随记录总量增长；两个存储之间没有统一快照。

缺失或较旧投影排入对应目标的 upsert／delete 事件，保留用户、版本、哈希与完整记录。已删除的孤儿墓碑保持不动；目标中的活跃孤儿在删除入队前复查权威源的准确 ID，减少扫描期间新增记录被误删的风险。该复查不是跨数据库原子事务，持续并发写入时仍可能出现短暂漂移，需要后续轮次收敛。

报告包含 Checked、Missing、Stale、Orphan、RepairEnqueued、RepairSkipped 和 Conflicts。只有实际插入或重新激活事件才计入 RepairEnqueued，去重或死信保留计入 RepairSkipped。目标版本领先、相同版本哈希冲突或活跃记录被同版本墓碑挡住时计入 Conflicts，不排入投影器必然拒绝的旧写入；需要重新对账或人工检查。修复事件处理完成后若再次漂移，相同 key 可重新激活；dead 事件需明确处理，不绕过重试上限。

已用分页仓储 Mock 覆盖分页边界、墓碑、孤儿复查、队列计数、错误和冲突，并将生成事件交给真实版本控制逻辑验证，再次扫描确认收敛。Milvus 使用安装的 SDK 与进程内服务替身检查主键迭代参数和解码，没有连接真实服务。对账只比较记录版本、哈希及删除标记，没有检查单条关系或每个目标字段的实际内容；应用层的定时调用仍待接入。

## 任务 DAG 模型

任务图定义 tool、sub_agent、think 和 aggregate 节点，以及依赖、竞速分组、执行状态、结果与重试次数。构造器复制参数和依赖、合并重复依赖；Validate 检查空节点、重复／空 ID、悬空依赖与环。拓扑层级按结构依赖重新计算，按节点 ID 稳定排序，不受执行入度消耗影响，返回值不会共享内部切片。

ReadyNodes 只返回当前可执行的 pending 节点。MarkDone 只消费一次就绪节点，保留失败、跳过或取消终态，并在所有依赖完成后释放下游；未知或重复完成保持不变。动态追加先注册整个批次以支持批次内前向依赖，验证通过才修改图；无效批次整体忽略，已有 ID 的结果不会被覆盖。竞速组成员、成功结果和摘要均保持稳定顺序。

已进行纯内存图检查，覆盖输入隔离、完成幂等性、执行后重新分层、动态依赖、原子追加、错误图与稳定输出。图对象及导出字段需要调用方同步；此模型没有执行工具、子 Agent 或并行调度，运行时与恢复路径仍在后续计划。

## 图记忆

图记忆包装长期记忆的过滤召回，用命中的种子读取已有 `Memory.memory_id` 节点的一跳关联，再从本地缓存回读。扩展读取 FOLLOWS、SIMILAR_TO、CAUSES 和 BELONGS_TO 关系，重新校验用户、分类、必需标签、年龄、隔离、替代与删除状态；审计开关仍需上层授权。图邻居使用固定 0.45 分数，与种子排序后按 TopK 截断，请求阈值高于 0.45 时跳过图扩展。没有种子就不查图。

Neo4j 不可用、查询失败或结果流失败时保留基础召回，不使用不完整的图结果。读图设置五秒截止时间，忽略空记录和无效 ID。现有公开构造器和代理方法保持兼容；旧 `Recall` 没有用户参数，按默认隔离规则返回空结果，应使用 `RecallByFilter`。

兼容 `Store` 只更新本地长期记忆，返回新增 ID 或同用户实际命中的首个活跃去重 ID；空用户写入沿用 legacy 归属。本包装实例协调并发 Store 与 ID 读取，直接操作底层 LTM 或共享 LTM 的其他包装实例仍需调用方同步。它不直接创建图节点或关系、不写 PostgreSQL，也没有自动关联文档实体；应用层已接入事务提交与冲突替代链路，持续投影调度仍待应用入口接入；图扩展需要已有节点和关系。

已通过九项离线检查、13 个子用例，覆盖普通与审计过滤、阈值与 TopK、连接降级、结果流错误、无效 ID、读取截止时间、去重 ID、元数据和并发 Store 返回值。使用合成数据与 Neo4j 驱动 Mock，未验证真实 Neo4j、数据库、图投影或 Go race 检测；完整应用仍在整合中。

## RAG 引擎

文档先按父块、子块两级切分，保存父块原文与文档版本元数据；父块大小为 `max(600, ChunkSize * 4)`。切分优先使用段落和句子边界，长句可按字符切开，完整代码块和重叠内容可能超过目标长度。无效切分大小与负重叠参数会规范到安全范围。

检索支持 Milvus 语义召回、Elasticsearch 关键词召回，以及可选图谱召回，用 RRF 按排名融合。跨查询按 PostgreSQL 行 ID 合并，保留不同文档中的相同文本及其父块来源。图谱只在 hybrid 路径且向量、关键词搜索均成功时参与；缺少向量回调或向量调用失败时降级为关键词检索。没有 PG 原文仓储时跳过入库与检索。

查询改写使用最近六条历史消息并保留原问题；模型输出无效时使用原问题。可选模型重排接受候选范围内的 0~10 评分，没有有效评分时保持原检索顺序。引擎用父块补充回答上下文，没有回答模型时返回检索原文。

新增文档写入失败不会关闭已有知识库。主仓储删除失败终止后续处理；删除后的状态刷新失败返回错误并保留最近状态，不意味着已完成的删除会回滚。索引写入、异步建图和跨后端删除均没有统一事务，`IndexedCount` 仅表示 PG 成功写入数量。`Loaded` 的并发读写需要调用方同步。

RAG 包测试覆盖切分边界、原查询保留、持久化 ID 合并、召回降级、读取错误、重排响应校验、元数据与父块传递、事件载荷、回答回调和知识库状态。使用合成数据、仓储 Mock 和模型回调；没有执行真实数据库、图谱、模型联通或应用 HTTP 测试。
