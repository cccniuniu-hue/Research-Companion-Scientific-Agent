# Research Companion Scientific Agent

面向研究与资料整理场景的智能助手，使用 Go 构建后端，Vue 3 构建交互界面。

项目围绕流式对话、文档检索、会话记忆、工具调用与多步骤任务执行逐步完善。技术路线采用 PostgreSQL 持久化、Milvus 向量检索、Elasticsearch 全文检索和 Neo4j 知识图谱。

## 会话记忆与偏好

短期记忆按 `MaxTurns * 2` 条消息维护最近窗口，提供追加、历史恢复、计数和快照；非正窗口保持为空。恢复历史保留输入时间，输入和快照均复制存储。模块自身使用进程内存；历史的数据库读取和用户分桶由后续应用层接入。公开方法持锁，直接访问导出字段需要调用方同步。

偏好模块支持单条与批量键值保存、快照和上下文格式化，忽略空键或空值。简单中文规则按“我喜欢／我爱／我叫”完整短语提取值；复杂语义和模型提取由上层处理。PostgreSQL 仓储按用户 ID 参数化保存与读取，行解析或结果流读取失败时记录日志并返回空结果，避免使用不完整的偏好。

长期记忆仓储保存用户 ID、原文、重要性、向量、分类、标签、槽位、隔离和替代关系，支持按用户读取、更新、批量重要性刷新、删除和隔离标记。`Load()` 会加载所有用户及 legacy 数据；调用方需按场景选择用户范围读取。更新与删除按条目 ID 执行，上层负责用户授权。

读取行或向量解析失败会丢弃整次结果。替代关系的旧记录标记与新记录链接在一个 PostgreSQL 事务中执行；新 ID 为正数时必须确认更新到一条新记录，链接失败或目标缺失会回滚。`newID == 0` 保留只标记旧记录的兼容路径。

已通过 14 项合成与 SQL Mock 检查，覆盖窗口边界、历史与快照复制、公开方法的并发调用、偏好规则、用户查询参数、元数据恢复、批量 SQL、读取错误及替代事务提交和回滚。没有验证真实 PostgreSQL 或运行 Go race 检测。仓储沿用无 error 返回值的接口，错误主要通过日志和空结果／失败 ID 表示；内存更新与仓储写入尚无统一事务。长期记忆领域层提供向量余弦召回和词袋降级，按用户、分类、标签与年龄筛选，默认排除隔离、已替代和已删除条目。隔离条目不会阻止同内容的新记忆写入。空用户写入归入 `legacy`，普通召回必须提供用户；全用户审计开关、按 ID 的操作及零新 ID 的替代兼容路径需要上层授权。输入、读结果和配置的可变字段均复制；直接访问导出字段仍需同步。

合并与去重只处理同用户、同分类的活跃条目，保留较重要条目的 ID、分类和来源标签，输出最终保留条目的更新；单条记忆也会衰减和按 TTL 淘汰。删除保护钩子可保留指定记录，隔离与已替代条目保留供审计。衰减以 `UpdatedAt` 为起点，旧数据回退到 `CreatedAt`，重要性差值达到 0.01 才生成衰减更新。该时间戳也用于其他写入，旧仓储没有保存衰减锚点，尚无跨重启的精确衰减保证。

`PlanConsolidation` 不修改缓存，生成携带预期版本的更新与删除计划；`Consolidate` 是直接修改内存并返回待写回结果的兼容入口，两者都没有自行执行 PostgreSQL 事务。新替代 ID 为正数时必须存在、归属一致且不能替代自身。

一致性契约包含版本化记录、Outbox 事件和已提交变更集。内容哈希复制并排序标签与替代 ID，规范删除时间的时区，拒绝非有限数值。`ApplyCommitted` 在修改前校验整批变更，拒绝重复 ID、现有记录的归属变化、过旧版本及同版本不同哈希；`ReplaceCommitted` 用权威记录重建缓存并排除墓碑。版本检查只覆盖仍在缓存中的记录，删除后的旧消息重放需要上层防护或权威重载。事务仓储已提供；Outbox 投影执行与应用层调度仍待后续整合。

本阶段 38 项测试、22 个子用例覆盖哈希边界、合并与衰减、版本校验、替代关系、用户隔离、隔离恢复、快照复制和公开方法并发调用。检查使用合成数据，未运行 Go race 检测或真实 PostgreSQL、图谱、向量与模型联通；完整应用尚不能启动。

## 记忆事务与 Outbox

事务仓储在同一个 PostgreSQL 事务中保存记忆、版本、内容哈希和对应的 Milvus／Neo4j Outbox 事件，只有数据库提交成功才返回变更集。创建支持可选关系事件；更新和软删除同时匹配条目 ID、用户 ID、预期版本及未删除状态。普通更新保留数据库中已有的隔离与替代元数据；哈希和事件载荷取自数据库返回的完整记录。

合并计划按 ID 顺序锁定条目，校验整批归属和版本，拒绝重复 ID。合并后的分类、标签、槽位、向量模型、访问时间、隔离与替代关系均写入；任何行、哈希、事件或提交失败都不返回部分已提交成果。活跃加载和分页属于内部恢复／对账接口，会读取所有用户；活跃加载只排除墓碑，调用方仍需控制授权和召回过滤。

Outbox 按目标和 ID 顺序用 `FOR UPDATE SKIP LOCKED` 领取待处理或租约已过期的事件，在同一事务内标记处理状态。处理中的 `available_at` 保存数据库时钟计算的租约截止时间；过期重新领取会累计中断尝试次数。成功、重试和死信更新要求事件仍为 processing，校验影响一行；重试保存下次可用时间、错误和尝试次数。修复入队按 key 去重，缺省事件 ID 根据 key 生成稳定 UUID。相同 key 已存在时跳过，包括已完成或死信事件。

当前投递语义是至少一次；状态接口只携带事件 ID，没有领取令牌和租约续期，不能阻止旧 worker 更新已被重新领取的事件。并发调度接入时需要处理此边界，投影器也需支持重复事件。投影器、消费调度和自动对账仍在后续计划，事务仓储本身不会连接向量或图服务。

事务与 Outbox 的 25 项测试、46 个子用例覆盖 SQL 参数、完整元数据与事件载荷、版本和用户归属、回滚、读取错误、领取租约、状态更新、修复 UUID 与去重。检查使用 SQL Mock，未在真实 PostgreSQL 执行 SQL、验证并发锁或故障恢复，也未运行 Go race 检测；完整应用仍在整合中。

## 图记忆

图记忆包装长期记忆的过滤召回，用命中的种子读取已有 `Memory.memory_id` 节点的一跳关联，再从本地缓存回读。扩展读取 FOLLOWS、SIMILAR_TO、CAUSES 和 BELONGS_TO 关系，重新校验用户、分类、必需标签、年龄、隔离、替代与删除状态；审计开关仍需上层授权。图邻居使用固定 0.45 分数，与种子排序后按 TopK 截断，请求阈值高于 0.45 时跳过图扩展。没有种子就不查图。

Neo4j 不可用、查询失败或结果流失败时保留基础召回，不使用不完整的图结果。读图设置五秒截止时间，忽略空记录和无效 ID。现有公开构造器和代理方法保持兼容；旧 `Recall` 没有用户参数，按默认隔离规则返回空结果，应使用 `RecallByFilter`。

兼容 `Store` 只更新本地长期记忆，返回新增 ID 或同用户实际命中的首个活跃去重 ID；空用户写入沿用 legacy 归属。本包装实例协调并发 Store 与 ID 读取，直接操作底层 LTM 或共享 LTM 的其他包装实例仍需调用方同步。它不直接创建图节点或关系、不写 PostgreSQL，也没有自动关联文档实体；事务与投影链路仍待后续整合，图扩展需要已有节点和关系。

已通过九项离线检查、13 个子用例，覆盖普通与审计过滤、阈值与 TopK、连接降级、结果流错误、无效 ID、读取截止时间、去重 ID、元数据和并发 Store 返回值。使用合成数据与 Neo4j 驱动 Mock，未验证真实 Neo4j、数据库、图投影或 Go race 检测；完整应用仍在整合中。

## 上下文组装

上下文按 chat、tool、rag、react 四种模式选择六类槽位：用户画像、任务规划、任务观察、工具状态、执行约束与长期记忆召回。不同槽位并发填充，同一槽位按注册顺序读取来源；单个来源失败保留其他来源的有效结果，请求取消时不使用部分结果。配置、来源输入中的可变切片与输出元数据均复制。来源需要提供并发安全的快照并响应 context。

画像先提供稳定排序的偏好，再读取本用户的长期记忆，按分类、标签、重要性与年龄过滤后统一截取 TopK。任务规划与观察必须匹配用户和任务；工具历史匹配用户及任务命名空间，工具目录可独立展示。缺少归属的旧记录不注入上下文。应用层创建／恢复规划快照及记录观察、工具结果时，还需接入可信 UserID、TaskID；相关运行时模块将在后续计划整合。

槽位与全局预算按 Unicode 正文字符数计算，默认全局 2400；标题、列表标记与间隔不计入，也不代表精确模型 token 数。单槽位保留连续完整项，全局优先移除召回、画像、工具等较低优先级内容。Required 只标记期望槽位，不生成占位文本或保证预算外内容保留。任务与工具摘要按 Unicode 边界截取，政策提示不替代沙箱实际校验。

当前上下文包的 40 项测试、11 个子用例覆盖配置和数据隔离、用户与任务边界、过滤顺序、预算与优先级、取消与错误降级、Unicode、快照和公开缓冲方法并发。使用合成数据与内存提供者；尚未执行模型调用、应用请求联通或 race 检测。完整应用仍在整合中。

## 工具执行

默认工具表提供模拟 `search_web`；Tavily 客户端通过 HTTP POST 获取答案和最多三条来源摘要。HTTP MCP 适配器向配置端点发送 JSON 参数，支持字符串与结构化结果、取消上下文和超时，并区分 HTTP 4xx、5xx 与网络错误的重试策略。

## 文档处理

## 知识图谱

Neo4j 连接模块执行 5 秒连通性检查，禁用配置或连接失败时跳过图操作。连接成功后尝试建立实体名称唯一约束、实体类型索引和记忆节点 ID 唯一约束；初始化失败记录日志，继续启动。

抽取器通过注入的模型回调解析实体关系 JSON，清理空名称、重复实体并规范七类实体与七类关系。图谱仓储用文档哈希、文本块编号和 PostgreSQL 行 ID 关联实体与关系，提供写入和删除。查询默认扩展两跳、最多三跳，按实体命中数和节点度评分并按 PGID 去重；APOC 执行或结果读取失败时降级为直接实体匹配，直接匹配读取失败返回空结果。非正结果上限跳过模型和数据库调用。

已通过本地断连、模拟模型回调和驱动检查，覆盖约束语句、会话关闭、抽取清理、参数化写入、删除范围、评分去重、跳数边界和读取失败。尚未验证真实 Neo4j、APOC 或模型服务；RAG 引擎支持注入图谱仓储，记忆业务与应用层接入仍待后续整合。

## RAG 引擎

文档先按父块、子块两级切分，保存父块原文与文档版本元数据；父块大小为 `max(600, ChunkSize * 4)`。切分优先使用段落和句子边界，长句可按字符切开，完整代码块和重叠内容可能超过目标长度。无效切分大小与负重叠参数会规范到安全范围。

检索支持 Milvus 语义召回、Elasticsearch 关键词召回，以及可选图谱召回，用 RRF 按排名融合。跨查询按 PostgreSQL 行 ID 合并，保留不同文档中的相同文本及其父块来源。图谱只在 hybrid 路径且向量、关键词搜索均成功时参与；缺少向量回调或向量调用失败时降级为关键词检索。没有 PG 原文仓储时跳过入库与检索。

查询改写使用最近六条历史消息并保留原问题；模型输出无效时使用原问题。可选模型重排接受候选范围内的 0~10 评分，没有有效评分时保持原检索顺序。引擎用父块补充回答上下文，没有回答模型时返回检索原文。

新增文档写入失败不会关闭已有知识库。主仓储删除失败终止后续处理；删除后的状态刷新失败返回错误并保留最近状态，不意味着已完成的删除会回滚。索引写入、异步建图和跨后端删除均没有统一事务，`IndexedCount` 仅表示 PG 成功写入数量。`Loaded` 的并发读写需要调用方同步。

RAG 包测试覆盖切分边界、原查询保留、持久化 ID 合并、召回降级、读取错误、重排响应校验、元数据与父块传递、事件载荷、回答回调和知识库状态。使用合成数据、仓储 Mock 和模型回调；没有执行真实数据库、图谱、模型联通或应用 HTTP 测试。

## RAG 评测数据

`test/test.txt` 是 JSONL 语料快照，包含 1,250 篇公开掘金文章的 10,000 个片段，保留来源 URL、文章与片段 ID、标题、作者、时间和内容 SHA-256。`test/gold.txt` 包含 50 个问题、每个问题五个相关片段引用，共 250 个引用；问题与文章绑定，分级按选中片段的位置设为 3、2、2、1、1。用于检索流程验证，报告准确率前需人工复核相关性分级。

生成器只使用 Python 标准库，采用 200 字符窗口和 50 字符重叠、固定种子采样、10,035 个候选片段和 35 个非 gold 片段删除。相同输入的选择过程确定；在线文章、站点地图及抓取时间变化会影响输出。运行 `python test/generate_real_rag_dataset.py` 会重新访问站点并替换两个数据文件。

生成前会清理 HTML 正文，并在切分与计算哈希前脱敏凭证样式的值。现有快照中 51 条记录经过脱敏，内容哈希已重新计算；原始片段 ID、来源元数据和 gold 引用保持不变。替换标记使其中 22 条记录超过原来的 200 字符窗口，最长为 214 字符，保留原片段边界以维持引用。

已完成八项离线生成器检查与全量快照校验，覆盖凭证模式、HTML 正文边界、Unicode 切分、固定输入构建、HTTP 重试、JSONL 写入、唯一 ID、来源、内容哈希和 gold 引用完整性。没有重新抓取网站，也没有运行真实检索服务或计算召回率、排序指标。现有快照不包含被删除片段的完整清单；模式脱敏仍需对新增凭证格式做人工复核。

## 环境要求

后端使用 Go 1.24.1，工具链固定为 Go 1.24.13。前端与部署模块整合后补充启动说明。

真实 API Key、JWT 密钥和本地运行数据通过本地配置或环境变量提供。

## 本地配置

`config/config.yaml` 通过 `LLM_API_KEY`、`EMBEDDING_API_KEY`、`TAVILY_API_KEY` 读取模型和搜索密钥；未设置时保持为空。`JWT_SECRET`、`PPROF_ADMIN_TOKEN`、`GITHUB_TOKEN` 也使用环境变量。可在已忽略的本地 `.env` 中配置；已有进程环境变量优先。

数据库地址和密码为本地开发示例，部署时应在本地覆盖。日志模块已验证请求 ID、用户 ID、空上下文与日志级别降级行为。
