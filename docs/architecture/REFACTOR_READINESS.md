# 已验证范围与后续改进

最终测试数字与执行环境见根 README。单元测试、sqlmock、本地 HTTP/TCP 和合成浏览器数据验证的是已覆盖代码路径，不能证明生产可用性或全部并发交错。

## 部署前待处理

| 项目 | 当前状态与后续验证 |
| --- | --- |
| PostgreSQL | 真实 DDL/upsert/事务未验收；Connect 的 Ping 失败分支仍未关闭新建的 sql.DB，生产前补充资源回收与超时测试 |
| 模型 SSE | 底层 llm.callAPIStream 未检查 scanner.Err，也不强制终止标记；可能把截断流作为部分成功。前端自己的 SSE 完成检查不能修复上游此行为 |
| 文档与 RAG | 共享管理范围，跨后端不原子；直接核心调用的 Loaded 并发仍需同步，缺少逐用户文档 ACL |
| Planner/任务 | 全局最近任务不是按用户的任务查询；并发任务 ID、恢复副作用、配额与后台抽取须在实际负载下验收 |
| Outbox/Milvus | 每目标单活消费者和单写者；租约不提供 fencing，长耗时或重启可能重复操作 |
| 对账 | 扫描不是共享事务快照，暂存记录占内存；验证真实迭代顺序、孤儿复核、dead/retry 策略和关系漂移 |
| 网络与工具 | MCP 地址格式检查不是网络白名单；沙箱/端点信任、外连策略与产物目录权限需独立配置 |
| 生产入口 | Compose/代理为本机评估模板；还需 TLS、CORS 策略、镜像漏洞审查、资源限额、备份、真实信号关停与恢复 |

这些是公开的已知限制，不以“完整代码整合”代替生产验证。核心源码中仍有历史 exec_command 装配注释，阅读应以 registerBuiltinTools、工具注册表与现行 HTTP 权限实现为准。

## 运行边界

- HTTP 普通用户只能访问自己的认证、会话相关业务、Skill 与活跃记忆。文档/RAG、全局状态、取消、快照、审计和 MCP 注册要求 JWT 加已配置的 `X-Admin-Token`。该令牌来自 `PPROF_ADMIN_TOKEN`，即使 pprof 关闭也用于管理权限；为空时拒绝管理操作。浏览器不内置此令牌。
- 每个共享 Agent 使用一个 HTTP Server 串行访问知识状态。直接调用核心 RAG 时仍需自行同步；同步 SQL/RAG 操作不保证及时取消，也不能撤回已发生的写入。
- 每个投影目标只运行一个活跃消费者，Milvus 保持单写者排序；缺少跨进程 fencing/CAS，不能水平扩容为多实例后宣称 exactly-once。
- 重试、竞速和快照恢复不保证外部副作用幂等。工具执行、模型/MCP 端点、工作目录和容器挂载必须另行建立信任与权限边界。
- PostgreSQL、Milvus、Neo4j、Elasticsearch、Kafka、模型、GitHub、MCP 和 Docker 尚未做真实服务联调。测试中的 mock/loopback 不能替代生产 schema、索引、权限、断线恢复与操作系统信号验收。
