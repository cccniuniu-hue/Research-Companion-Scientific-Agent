# 上下文组装

`ContextAssembler` 根据 chat、tool、rag、react 选择槽位配置。未知模式回退到配置中的 chat；没有该配置时结果为空。六类槽位依次由画像、规划、任务观察、工具状态、沙箱政策和长期记忆召回来源填充。不同槽位并发，同一槽位的来源按注册顺序执行；提供者需要支持并发访问并返回稳定快照。

`DefaultSchemas` 与装配器构造、返回结果均复制槽位的嵌套切片。每次来源调用获得独立的过滤切片和查询向量，返回项的元数据也复制，避免调用方或另一个来源修改共享状态。

## 过滤与预算

画像偏好按键排序并优先于长期记忆；长期记忆先按用户、分类、标签、重要性与年龄筛选，再对合并结果应用 TopK。结构化偏好没有标签，不能满足必需标签条件，分数为 1。Recall 将用户、查询、向量和过滤条件传给 LongTerm 或 GraphMemory；匿名画像与召回请求不读取个人数据。

来源先做适用的领域过滤，装配器统一执行最终槽位 TopK 与正文预算。预算计算 Unicode 码点，不是 UTF-8 字节，也不是模型 token。单槽位保留能放入预算的连续完整项；遇到第一个放不下的项就停止，不拆项。默认全局正文预算为 2400 字符；超限时按 Recall、Profile、ToolState、TaskMem、Planner、Constraints 的次序，从各槽位尾部移除完整项。标题、列表标记与槽位间隔不计入该预算；需要精确模型 token 上限时应接入模型分词器。

`Required` 表示期望的数据，不强制保留预算外内容，也不生成占位文本。空白和空槽位不渲染。`Template`、`Trace` 保留为接口字段，目前分别按 Kind 渲染、保持为空。来源错误记录在 FilledSlot.Reason 中并继续其他来源；请求取消后不返回已收集的部分内容。装配器会等待 Fetch 返回，无法强制中止不响应 context 的提供者。

## 用户与任务边界

PlannerSnapshot 必须带匹配的 UserID、TaskID。StepObservation 同时记录 UserID、TaskID；没有完整查询归属、记录归属不匹配或记录过期时不注入任务观察。ToolCallTrace 也按用户和任务过滤，空 TaskID 单独作为同用户的单工具调用命名空间。工具目录可以独立于私人调用历史展示。任务和工具缓冲区的容量是整个实例的上限，没有按用户单独分配容量。

应用层在创建、恢复规划快照和记录工具结果时必须从可信请求、任务上下文填写这些归属字段，不能由模型输出决定。当前只完成领域层，core_agent.go、runtime_graph.go、mode_tool.go 等应用层调用将在其计划阶段接入；未带归属的旧记录会被忽略。

TaskMemBuffer 和 ToolStateTracker 提供持锁写入与独立快照；观察摘要与工具摘要分别按 200、120 个 Unicode 字符截取并追加省略号。沙箱政策文本只是上下文提示，实际执行仍须经过已有校验器。此模块没有调用模型或执行工具。
